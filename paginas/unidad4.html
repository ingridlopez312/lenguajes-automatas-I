Unidad 4: Análisis Léxico

En esta unidad se estudia la primera fase de un compilador: el análisis léxico. Se explican los conceptos de token, lexema, patrón, tabla de símbolos, errores léxicos y el proceso mediante el cual el código fuente se convierte en una secuencia de tokens.

Objetivo de la unidad

Comprender el funcionamiento del analizador léxico dentro de un compilador, identificando cómo se reconocen tokens, lexemas y patrones a partir de un código fuente, así como la importancia de detectar errores léxicos.

4.1 ¿Qué es el análisis léxico?

El análisis léxico es la primera fase de un compilador. Su función principal es leer el código fuente carácter por carácter y agrupar esos caracteres en unidades significativas llamadas tokens.

Esta fase actúa como un filtro inicial. Elimina espacios innecesarios, saltos de línea y comentarios, mientras identifica elementos importantes del lenguaje como palabras reservadas, identificadores, operadores, números y signos de puntuación.

Código fuente
→
Analizador léxico
→
Tokens
→
Analizador sintáctico
Dato importante:

El analizador léxico no revisa si una instrucción está bien estructurada gramaticalmente; esa tarea corresponde al análisis sintáctico.

4.2 Token, lexema y patrón

Para comprender el análisis léxico es necesario diferenciar tres conceptos: token, lexema y patrón. Estos elementos permiten clasificar el contenido del código fuente.

Concepto Definición Ejemplo
Token Categoría o tipo de unidad léxica. IDENTIFICADOR
Lexema Texto real encontrado en el código. edad
Patrón Regla que describe la forma válida de un lexema. [a-zA-Z_][a-zA-Z0-9_]*
Ejemplo:

int edad = 20;

int → PALABRA_RESERVADA

edad → IDENTIFICADOR

= → OPERADOR_ASIGNACION

20 → NUMERO_ENTERO

; → PUNTO_Y_COMA

4.3 Clasificación de tokens

Los tokens permiten clasificar las partes del código fuente. Cada lenguaje de programación define sus propios tokens de acuerdo con su sintaxis.

Tipo de token Descripción Ejemplos
Palabra reservada Palabras propias del lenguaje. int, if, while, return
Identificador Nombres definidos por el programador. edad, suma, contador
Número Valores numéricos. 10, 20, 3.14
Operador Símbolos que realizan operaciones. +, -, *, /, =
Separador Símbolos que delimitan instrucciones. ;, (, ), {, }

4.4 Relación con expresiones regulares

Los patrones léxicos suelen definirse mediante expresiones regulares. Por ejemplo, un identificador puede definirse como una letra seguida de letras o números. De esta manera, las expresiones regulares ayudan al analizador léxico a reconocer cadenas válidas.

Identificador: [a-zA-Z_][a-zA-Z0-9_]*
Número entero: [0-9]+
Número decimal: [0-9]+\\.[0-9]+
Operador: \\+ | \\- | \\* | / | =

4.5 Proceso del analizador léxico

El analizador léxico realiza un proceso sistemático para transformar el código fuente en tokens. Este proceso puede dividirse en varios pasos.

Paso Descripción
1. Lectura Lee el código fuente carácter por carácter.
2. Agrupación Agrupa caracteres para formar lexemas.
3. Comparación Compara lexemas con patrones definidos.
4. Clasificación Asigna un token a cada lexema.
5. Envío Envía los tokens al analizador sintáctico.

4.6 Tabla de símbolos

La tabla de símbolos es una estructura de datos utilizada por el compilador para almacenar información sobre identificadores, variables, funciones, constantes y otros elementos del programa.

Aunque comienza a utilizarse desde el análisis léxico, también es importante en fases posteriores como el análisis semántico y la generación de código.

Identificador Tipo Valor Ámbito
edad int 20 global
promedio float 9.5 local

4.7 Errores léxicos

Un error léxico ocurre cuando el analizador encuentra un símbolo o secuencia que no pertenece al lenguaje. Estos errores suelen aparecer por caracteres inválidos, identificadores mal formados, números incorrectos o símbolos no reconocidos.

Error Ejemplo Explicación
Carácter inválido @edad El símbolo @ no está permitido al inicio.
Número mal formado 12.3.4 Contiene más de un punto decimal.
Identificador inválido 2nombre No puede iniciar con número.

4.10 Aplicaciones del análisis léxico

El análisis léxico tiene aplicaciones importantes en compiladores, intérpretes, editores de código, IDEs, validadores de sintaxis y herramientas de análisis de software.

Aplicación Uso
Compiladores Identifican tokens antes del análisis sintáctico.
IDEs Resaltan palabras reservadas y errores.
Intérpretes Procesan instrucciones durante la ejecución.
Analizadores de código Detectan errores o patrones incorrectos.

Actividad 3:

Actividad 4:

Conclusión de la unidad

El análisis léxico es una fase fundamental dentro del proceso de compilación, ya que transforma el código fuente en una secuencia organizada de tokens. Gracias a esta etapa, el compilador puede interpretar el código de manera estructurada y enviarlo a las fases posteriores.

Los conceptos de token, lexema y patrón son esenciales para comprender cómo los lenguajes de programación son procesados internamente. Además, el uso de expresiones regulares y autómatas finitos permite construir analizadores léxicos eficientes y precisos.
